# 2026-09-03 — Onboarding v4: monochrome rebuild from scratch

## TL;DR

Rebuilt onboarding again, from scratch, per a detailed screen-by-screen spec:
**splash → value prop → interests (6-category grid) → religion practice
(conditional branch) → age slider → expectations → notification preview →
CEO thank-you**. Switched onboarding to a monochrome charcoal-gradient
palette (explicitly an *experiment scoped to onboarding*, not a decision
about the rest of the app) with Google Sans Flex headers. **Deleted** the
v3 paywall and login/signup screens entirely (not mocked — gone). Started
in Figma (4 screens built + screenshot-verified as real, editable layers)
until the plan's monthly call cap cut that off; finished the rest directly
in code and verified the whole flow by actually running the app, not just
`tsc`. Also fixed a real pre-existing bug (notification permission was
never requested) and exported the hand-drawn illustrations as standalone
SVG/PNG files.

## What changed

**Onboarding (`src/components/onboarding/`)** — full rewrite:
- **welcome.tsx** (splash) — "quotable!" / "your pocket cheerleader" / white
  pill button, no back arrow (nothing to go back to), skip × only.
- **value-prop.tsx** *(new)* — value-prop sentence + hand-drawn illustration
  (book/sunflower/two-stick-figures photo).
- **interests.tsx** *(replaces categories.tsx)* — new 6-category grid
  (Sports/Meditation/Politics/Religion/Anime/Nature), a broader "what
  inspires you" taxonomy than the app's quote-tone MOODS. Bridged back to
  the real `MoodId`/`Tone` system via `INTEREST_TO_MOOD` so Explore and the
  live quote generator still work off what's picked here.
- **religion.tsx** *(new)* — "What do you practice?" emoji list, only
  shown if Religion was picked. Selection is stored (`religiousPractice`
  on `OnboardingProfile`) but not yet surfaced anywhere else in the app.
- **age.tsx** *(new)* — 16–75+ slider (`@react-native-community/slider`),
  stored as `age` on `OnboardingProfile`. No v3 equivalent.
- **expectations.tsx** *(new)* — icon row (wallpaper/music/chess/mountain
  climber), pure marketing, nothing stored.
- **notification-preview.tsx** *(new)* — 3 mock push-notification cards:
  a joke one ("Saul Goodman," the fictional Better Call Saul lawyer —
  confirmed as a deliberate wink, not a real quote), plus two real,
  correctly-attributed quotes (Buddha, Muhammad Ali).
- **cta-thankyou.tsx** *(new)* — "Hey! This is the Quotable CEO!" +
  "be quotable!" final button → `completeOnboarding()`.
- **Deleted**: `paywall.tsx`, `account.tsx` (v3's mock sign-up/log-in —
  `signUp`/`logIn`/`account` still exist in `app-state.tsx`/`storage.ts`
  but nothing in the UI reaches them anymore, confirmed nothing else calls
  them), `mood-chip.tsx`, `notify-time.tsx`, `wheel-time-picker.tsx`
  (v4 has no dedicated notify-time screen — see below), `illustrations.tsx`
  ("Corporate Memphis" style, replaced by `stick-art.tsx`'s hand-drawn
  single-stroke style), `categories.tsx`, `option-card.tsx` (already dead).
- **onboarding-flow.tsx** — rewired around a step *history stack* (push/pop
  step names) instead of a flat array index, because the Religion branch
  means "back" isn't always "index − 1".
- **skip-back-row.tsx** *(new)* — shared back-chevron + skip-× control on
  every screen but splash, each wired to `haptics.tap()` + `sound.squish()`.

**Theme (`src/constants/theme.ts`)**
- `OnboardingColors`: warm cream/coral/sunflower/lavender → charcoal-to-
  faded-grey `gradientStops`, consumed via `expo-linear-gradient` on every
  screen. **This retires** the old "eventually becomes the whole app's
  theme" plan — user confirmed monochrome is onboarding-only, for now.
- `BrandFonts`: added `googleSansMedium/SemiBold/Bold` via the newly-
  installed `@expo-google-fonts/google-sans-flex`. Plain "Google Sans" is
  still not on Google Fonts; the variable "Google Sans Flex" was
  open-sourced onto Google Fonts in late 2025 and is what's actually used.
  Urbanist font loading removed from `_layout.tsx` (no longer used anywhere).

**Data model**
- `OnboardingProfile` (`storage.ts`) and `OnboardingResult`
  (`app-state.tsx`): added optional `religiousPractice`/`age`.
- No dedicated notify-time picker screen in v4 (cut along with
  paywall/account, per the spec) — `completeOnboarding()` now schedules at
  `DEFAULT_NOTIFY_TIME` (9:00 AM) instead of a user-chosen time.

**Bug fix (unrelated to the rebuild, found by accident)**
- `requestNotificationPermission()` existed in `lib/notifications.ts` but
  **nothing ever called it** — `scheduleDailyQuote()` called
  `scheduleNotificationAsync` directly and silently swallowed any
  permission failure. The daily notification has likely never actually
  fired for anyone unless the OS happened to already have permission from
  elsewhere. Fixed: `completeOnboarding()` now calls
  `requestNotificationPermission()` before scheduling.

**New assets**
- `assets/onboarding-illustrations/` — the 6 hand-drawn illustrations
  (previously inline-only React Native SVG code in `stick-art.tsx`) also
  exported as standalone files: `value-prop.svg`/`@2x.png`,
  `icon-{wallpaper,music,chess,climb}.svg`/`@3x.png`,
  `waving-figure.svg`/`@2x.png`. Dark (#19191B) strokes on transparent
  background, since the app's inline versions are white-on-gradient but
  these exports are meant for external use (docs, sharing, previewing on a
  normal white background).

**Figma**
- Built + screenshot-verified 4 screens as real Figma layers in a new
  "Wireframes for Quotable" page (Splash, Value Prop, Interests, Religion),
  before hitting the Starter-plan's 20-calls/month cap on the MCP server —
  turns out write calls (`use_figma`) aren't exempt from that cap either,
  despite what the plan's exemption-list docs implied (only
  `create_new_file`/`whoami`/`add_code_connect_map` actually are). User
  chose to finish the remaining 4 screens directly in code rather than
  upgrade the seat.

**Verification**
- `tsc --noEmit` and `npm run lint` both clean.
- Actually ran the app (`npx expo start --web`, driven via claude-in-chrome
  browser automation) rather than trusting the typecheck alone — this
  caught two real bugs neither Figma's preview nor `tsc` would have:
  react-native-svg's `rotation`/`origin` shorthand throws an "Invalid DOM
  property" console error on web (fixed: use
  `transform="rotate(deg,cx,cy)"` instead); onboarding had no web
  max-width constraint, so the Expectations icon row stretched edge-to-edge
  on a wide desktop viewport (fixed: applied the same
  `maxWidth: MaxContentWidth` pattern `app-tabs.web.tsx` already uses).
  Clicked through the entire 8-screen flow twice end-to-end, including the
  Religion branch and full completion → landed cleanly on Today with zero
  console errors.

## Things to watch for

- The Interests → Religion branch relies on `history` (a stack of step
  names) in `onboarding-flow.tsx`, not a flat step index like v3 used. If
  you add another conditional branch later, follow the same pattern —
  don't go back to an array index, it won't handle branches correctly.
- `OnboardingColors.gradientStops` is a 3-stop tuple consumed positionally
  by `expo-linear-gradient` in both `onboarding-scaffold.tsx` and
  `welcome.tsx` (`locations={[0, 0.55, 1]}`) — if you ever change the
  number of stops, update both call sites' `locations` array too.
- The Figma file's "Wireframes for Quotable" page only has 4 of the 8
  screens (Splash, Value Prop, Interests, Religion) — Age/Expectations/
  Notification/Thank-you exist only in code, not in Figma, because of the
  plan cap. Don't assume Figma is the source of truth for the whole flow.
- Notification quotes in `notification-preview.tsx` are hardcoded example
  content (Saul Goodman joke + Buddha + Muhammad Ali), not pulled from
  `LIBRARY` in `constants/library.ts` — if that quote bank changes, this
  screen won't notice.
