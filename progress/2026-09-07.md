# 2026-09-07 — Explore rebuild: Pinterest+Goodreads feed, libraries, and polish pass

## TL;DR

Rebuilt Explore into the app's real center of gravity: a 3-tab nav
(Home/Explore/Wallpaper, Me demoted to an avatar-triggered overlay), a
Pinterest-style masonry feed browsable by topic, real public-domain photos
for every category, a Pinterest-style full-screen post detail view with a
long-press emoji reaction picker, and a Spotify-style "save to library"
picker (Favorites + user-created libraries) off a lavender Favorite button.
Iterated heavily against the user's own phone screenshots to catch things
desktop-only testing missed (masonry overflow, invisible pin text, a broken
shuffle). Closed today by fixing a real Modal-layering bug in the library
picker and swapping the poster row's `@handle` for each creator's
customizable bio line.

## What changed

**Nav (`src/components/app-tabs.tsx` / `.web.tsx`)**
- Trimmed to 3 tabs: Home / Explore / Wallpaper, icons only (no labels).
  `NativeTabs` gets iOS 26 Liquid Glass automatically — no glass-specific
  code needed, confirmed against the SDK 57 docs.
- Feed tab retired; its "creator posts + following" idea folded into
  Explore. Me left the tab bar — now `src/components/profile-overlay.tsx`,
  opened via `openProfile()` (`src/lib/profile-bus.ts`) from avatar buttons
  on Home/Explore.

**Explore taxonomy (`src/constants/topics.ts`)**
- New `TopicId`: For You / Anime / Politics / Workout / Family / Music /
  Romance / Travel — curated separately from `MoodId` (which keeps driving
  Studio presets/onboarding/tone untouched).
- Every topic now carries a `blurb` (e.g. "fuel for the last rep" for
  Workout) shown as a subheader under both the landing "explore" title and
  each category's heading.
- Anime/Politics/Workout have real photos + full content; Family/Travel are
  real, clickable, empty-state-only categories; Music/Romance reuse
  existing quotes with no curated photo.

**Real photos (`src/constants/photos.ts`)**
- Every one of the 8 category tiles now has a real cover photo, plus
  per-quote photos for Anime/Politics/Workout.
- **Public-domain only, by explicit decision.** Sourced from Unsplash
  (`scripts/fetch-unsplash.ts` to search, `scripts/trigger-unsplash-download.ts`
  to ping `download_location` per their API Guidelines) and Wikimedia
  Commons (license verified via its `imageinfo` API). A Mandela portrait
  was added, found to be CC BY 2.0 (not public domain), and **removed
  entirely** rather than building attribution UI for it — no photo ships
  without a clean public-domain/Unsplash license.
- Never used Google Images/SerpApi scraping or AI-generated fake imagery of
  real people, per the user's standing instruction.

**Masonry feed (`src/lib/explore-feed.ts`, `src/components/quote-masonry.tsx`)**
- Fixed a real shuffle bug: sorting by `hash(id)` wasn't a shuffle — short
  ids clumped together (invisible on paper, obvious once real data was in
  the feed). Replaced with a proper seeded Fisher-Yates (mulberry32 PRNG).
- Fixed invisible pin-card text: ink color was hardcoded instead of reading
  `presetById(presetId).ink`, so some presets rendered white-on-white.
- `creatorForPin()` now deterministically hash-assigns every quote-only pin
  one of 4 fictional `CREATORS` — every post has a proper account, never a
  raw photo credit, and no real photographer is misattributed as a social
  persona.

**TopicGrid (`src/components/topic-grid.tsx`)**
- Caught from the user's own phone screenshot, not desktop testing: fixed
  `width:'48%'` + fixed `gap` overflowing past 100% on real narrow screens.
  Switched to `justifyContent:'space-between'` + `width:'47%'`.
- Label bumped to 24px, centered, white-on-thumbnail.

**Explore screen (`src/app/explore.tsx`)**
- Search bar and Following toggle removed from the header "for now" per
  explicit instruction — `filterExplorePosts`/`FollowingEmpty` logic is
  still there, just unreachable from the UI until there's a new entry point.
- Category header rebuilt: big gray circular back button (shared
  `src/components/back-button.tsx`, same one used in `PostDetailOverlay`),
  proper large heading + a blurb subheader underneath, with
  `marginTop: Spacing.one` giving the two lines actual breathing room
  (today's last spacing fix, verified in-browser).

**Post detail overlay (`src/components/post-detail-overlay.tsx`)** — most
heavily iterated file this session:
- Rebuilt to mirror Pinterest's own post view: a large rounded-corner
  (`borderRadius: 24`) image frame that dominates the screen (not literally
  edge-to-edge — corrected after an over-literal first pass), a translucent
  floating `BackButton` overlaid on the image's top-left corner, an
  optional caption, then like/comment/share grouped tight on the left with
  the lavender Favorite pill pushed to the far right.
- **Every post shows a real account, never a photo credit.** The poster row
  always reads from `post.creator` (unified type across social + pin
  posts) — no more "photo: X · Unsplash" fine print under any post.
- **Today's change**: replaced the `@handle` line with `creator.bio` (the
  same customizable-blurb field already on `Creator`, e.g. "Tender lines
  for slow evenings and people you love." instead of "@softhours"), and
  made the avatar a `Pressable` so it reads as tappable. Added
  `flexShrink: 1` + `numberOfLines={1}` on the text column so longer bios
  wrap/truncate cleanly instead of overflowing the row.

**Reactions (`src/components/like-heart.tsx`, `reaction-picker.tsx`,
`src/lib/haptics.ts`, `app-state.tsx`, `storage.ts`)**
- Tap toggles the existing like; long-press (`delayLongPress={350}`) opens
  a 20-emoji curated grid, multi-select, backdrop-press-to-dismiss.
- New `reactions` state (`Record<string,string[]>` keyed by trimmed quote
  text) + `toggleReaction`/`reactionsFor`, persisted via
  `KEYS.reactions`/`loadReactions`/`saveReactions`.

**Libraries / Favorite picker (`favorite-button.tsx`, `library-picker.tsx`,
`app-state.tsx`, `storage.ts`, `constants/quotable.ts`)**
- Favorite button no longer directly toggles a single favorite — tapping it
  opens `LibraryPicker`, a Spotify-style "Add to Playlist" sheet: Favorites
  pinned first, then every user-created `Library`, then "+ create new
  library" (inline `TextInput` → `createLibrary()` → immediately
  `addToLibrary()`).
- New `Library` type (`quotable.ts`), `libraries` state +
  `createLibrary`/`addToLibrary`/`removeFromLibrary`/`isInLibrary` on
  `app-state.tsx`, persisted via `KEYS.libraries`.
- Favorite pill reads "✓ favorited" (deep lavender) whenever the quote is
  saved *anywhere* (Favorites or any library), else pale "favorite".
- **Bug found and fixed today**: `LibraryPicker`'s popup was a plain
  `position: absolute` View, but it's mounted inside
  `PostDetailOverlay`'s `ScrollView` — on web that ancestor clipped/scrolled
  it instead of letting it float over the whole screen, so the sheet
  rendered as a broken, partially-transparent strip (title bar visible,
  "favorites" row and list invisible, content bleeding through from the
  page behind it). **Fixed by wrapping it in RN's `Modal`**, which portals
  to a top-level layer regardless of where it's mounted in the tree — the
  correct general pattern for any popup opened from inside a scrollable
  ancestor.

## Verification

- `tsc --noEmit` and `npm run lint` clean throughout.
- Drove the real app via `npx expo start --web` + claude-in-chrome for
  every change: clicked through category tiles, opened post detail on both
  photo and plain-paper posts, confirmed the bio now shows instead of a
  handle, opened the Favorite picker, toggled Favorites, created a new
  library ("date night") and confirmed it persists checked, confirmed the
  pill flips to "✓ favorited".
- Checked layout at both wide desktop and true ~375px width (the
  `document.documentElement.style.width` injection trick) per the standing
  memory — **found a real limitation**: this trick doesn't reach `Modal`
  content, since `Modal` portals against the actual browser viewport, not
  the artificially-narrowed `<html>` element. Confirmed the sheet's own
  styles are pure `left:0/right:0/bottom:0` percentage layout with no fixed
  desktop widths, so there's no reason to expect a mobile-specific bug —
  but it genuinely wasn't visually re-confirmed at 375px the way everything
  else was.
- Closed a stray, unrelated YouTube tab that had wandered into the browser
  tab group mid-session.

## Things to watch for

- `creatorForPin()` in `lib/explore-feed.ts` is a plain hash over quote id
  — deterministic and stable, but if `CREATORS` ever changes length or
  order, every quote's assigned creator will shift. Fine for a no-backend
  seeded app, just don't be surprised by it.
- The `LibraryPicker` Modal fix is the pattern to copy for any *future*
  popup opened from a component that itself lives inside a `ScrollView`
  (e.g. if `ReactionPicker` or anything else ever gets nested somewhere
  scrollable) — a plain `position: absolute` View is not enough on web.
- CLAUDE.md's "Product surface" section already documents the 3-tab
  structure, Explore's two-screen shape, and the Me-as-overlay pattern as
  current — it was kept in sync with this rebuild, not left describing the
  old 5-tab layout.
- Explore intentionally uses its own font (`BrandFonts.valley*`, Valley
  Sans) and shows full-color photos for 3 categories — both are documented
  exceptions to the app's otherwise strict black-and-white/Indie-Flower
  rule, not accidental drift.
